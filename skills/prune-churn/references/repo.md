# Repo and process

Files, tooling and policy that make every change drag extra edits along. Report by default: each finding gets its sites, the `cochange.py` tag-along count when mined, and the suggested shape. Edit only where **Do** says so, and only what the current change introduced. Never touch gitignored files, untracked files outside the scope, CI gates or formatter config. You rarely know what the change was asked to do: a file, knob or dependency the request named is never a finding.

### Session artifacts

- **Tell**: files describing a moment rather than the system (tracked, or untracked in `diff` scope): `git ls-files --cached --others --exclude-standard | grep -iE '(SUMMARY|REPORT|PLAN|PROGRESS|STATUS|IMPLEMENTATION|ANALYSIS|FINDINGS)[^/]*\.md$'`; a copy matching `(_old|_backup|_copy|\.bak|\.orig)(\.\w+)?$` whose original sits beside it; root-level `scratch*`, `tmp*`, `debug_*`, `verify_*` scripts that no runner, CI job or task file references and the test runner doesn't collect; prose with `Phase 2`, `Status:`, `next steps`, `will be implemented`, `we just added`, checkbox progress lists.
- **Do**: if the current diff added it, delete it. Move anything durable first: a trap → a comment at the trap; a decision → the existing topic doc, or an ADR if the repo keeps them; the plan or summary → your report, for the PR description. Older ones: report.
- **Keep when**: ADRs and RFCs; a ROADMAP a person owns; CHANGES, NEWS and release notes; user-facing MIGRATION/UPGRADE guides; anything in a migrations dir; versioned code (`api_v2.py`, `client_new.ts`) something imports; files linked from the README or a docs index; plans checked in by explicit team convention for a multi-PR effort. Never search gitignored files.

### Generated output without a regen gate

- **Tell**: `@generated`, `DO NOT EDIT`, `Code generated by` headers; committed API clients, protobuf stubs, option/doc references, compiled CSS; no CI step that reruns the generator and fails on diff; commits editing generated output without its source, or the source without the output.
- **Do**: if the change hand-edited generated output, move the edit into the source and rerun the generator; if it changed the source, regenerate. No runnable generator → report. Gate shape: gitignore the output and generate at build, or commit it and gate CI with `<generate> && git add -A && git diff --cached --exit-code` (plain `git diff --exit-code` misses new and deleted files); `linguist-generated=true` in `.gitattributes` so review collapses it; agent files point at the generator command, not the output.
- **Keep when**: lockfiles; consumers must build without the generator (templ `_templ.go`, `go generate` in libraries); slow or non-hermetic generators; vendored dependencies kept as deliberate snapshots.

### Nondeterministic output

Machine-written files only. Hand-written config, manifests and fixtures are out of scope.

- **Tell**: generating twice in a row leaves a diff; `*.ipynb` with non-empty `outputs` or non-null `execution_count`; `Generated (on|at) <date>` or tool-version headers; generated JSON/YAML with unsorted keys or on one long line; absolute paths (`/home/`, `/Users/`, `C:\`) in committed output; exported dashboards or diagrams with volatile ids.
- **Do**: report the generator fix: sorted keys (`sort_keys=True`, stable map iteration), no timestamps or honour `SOURCE_DATE_EPOCH`, relative paths, one key per line; notebook outputs stripped by a git filter or pre-commit hook (e.g. `nbstripout`); a CI step that generates twice and expects no diff.
- **Keep when**: notebooks published as reports, where outputs are the deliverable; headers carrying a schema version needed to reproduce the output; minified assets meant to ship as-is.

### Layout the formatter doesn't own

- **Tell**: runs of 3+ lines padded to one column (`grep -nE '\S {2,}(=|:|#|//)'`); multi-line literals or argument lists without a trailing comma where the language allows one; Markdown or docstrings hard-wrapped so a one-word edit reflows 3+ lines; order-free lists (dependencies, CODEOWNERS, enums) every PR appends to the tail; formatter or package manager unpinned (caret-ranged formatter, no `packageManager` field, no version file or devshell); CI without a format check or frozen-lockfile install; `git diff -w --stat` far smaller than `git diff --stat`; lockfile format version flipping in history.
- **Do**: never hand-reformat. Report the config change: trailing commas on, alignment options off, a sort rule for order-free lists, semantic line breaks with prose wrap preserved; exact formatter and package-manager versions; format check and frozen lockfile in CI; formatter upgrades as standalone commits listed in `.git-blame-ignore-revs`.
- **Keep when**: alignment that carries meaning (test-case tables, bit layouts, keymaps) and a tool maintains it; order-significant lists (middleware chains, plugin priority, migration order), which must never be sorted; libraries testing against runtime ranges (pin the formatter, not the matrix); tiny throwaway repos.

### Location-keyed suppression baselines

- **Tell**: a committed checker baseline (`*baseline*`, `eslint-suppressions.json`, `.betterer.results`) whose entries are keyed by line number or per-file count; a baseline with a high tag-along rank, or regenerated in PRs that only moved code.
- **Do**: report. Shape: key entries by rule plus symbol or fingerprint instead of line or count; make it a shrink-only ratchet and burn it down rather than regenerating.
- **Keep when**: adopting a strict checker on legacy code, where a baseline is the only way to enforce the rule on new code, as long as it only shrinks. Inline suppressions travel with their line and are not this finding.

### Shared changelog edited by every PR

- **Tell**: `CHANGELOG.md` with a high tag-along rank or touched by most non-release commits; a Danger rule or PR checkbox demanding an entry; an `## Unreleased` section with conflict-resolution commits.
- **Do**: report the policy. Shape: generated from Conventional Commits for solo or low-concurrency repos; per-PR fragment files when PRs run concurrently (they remove conflicts, not files touched). Leave entries the repo's policy requires. `Recent changes` sections in READMEs or agent files are `docs.md` findings; a version bumped by hand in several files is a `structure.md` finding.
- **Keep when**: curated release notes written once per release. In solo repos rate it low severity.

### Gates that mandate co-changes

- **Tell**: docstring-coverage thresholds (`interrogate --fail-under`, ruff/pydocstyle `D1xx` on private code and tests); coverage thresholds at 100 (`fail_under = 100`, `coverageThreshold`); Danger or CI rules failing when src changes without tests or docs; many `# noqa: D1` or `# pragma: no cover` (people fighting the gate).
- **Do**: report only; never edit CI rules or thresholds. Cite the filler the gate produced as evidence. Shape: docstrings required on the public API only; coverage on changed lines with a sane floor, or mutation score; no "tests must change" rules; consistency checks (link checks, regen diffs, doctests) over volume checks.
- **Keep when**: published libraries, where public API docs are user value; regulated safety-critical coverage; gates that verify generated docs are in sync.

### Speculative configurability

- **Tell**: new env reads (`os.environ.get`, `process.env`, `getenv`), CLI flags or config keys where no call site, env file, deploy manifest, CI job or test sets a non-default value; parameters every call site leaves at the default; feature flags at one value in every environment the repo can see; schema or default keys nothing reads.
- **Do**: in `diff`, inline a knob only when this change introduced it, the repo sets it nowhere, and it isn't public API; name in the verdict the docs rows and tests that only exercise the removed branch; they are removed after this pass. Otherwise report never-varied knobs and finished flags with their call sites. Never hard-code secrets or per-environment endpoints.
- **Keep when**: values that differ per environment (URLs, credentials, resource limits); operational kill switches; library APIs where callers need the control; values set outside the repo (flag service, deploy config elsewhere): report, don't inline.

### Dependency sprawl

- **Tell**: two packages for one job (`moment` + `dayjs`, `axios` + `got`, `requests` + `httpx`); a dependency imported in one place for one small function the stdlib or an existing dependency provides; unused dependencies (an unused-dependency checker, a `go mod tidy` diff).
- **Do**: if the change added a dependency it never imports or invokes, remove it from manifest and lockfile. If it added one an existing dependency or the stdlib covers with an equivalent call, switch to that only when tests cover the call site; otherwise report. Report older overlaps and unused dependencies with import-site counts; shape: consolidate, and run the unused-dependency checker in CI.
- **Keep when**: crypto, parsing, date/timezone math, Unicode: a vetted library beats hand-rolled code. Not unused just because nothing imports it: plugins and presets loaded by config, type stubs (`@types/*`), peer dependencies, CLIs called from scripts or task files, runtime drivers loaded by name.

### Migration sprawl

- **Tell**: several migrations in one branch on the same table or column (add, then rename or alter); edits to migrations already on the default branch; numbering conflicts, merge migrations, multiple heads; large schema dump or ORM snapshot diffs unrelated to the branch's own migration.
- **Do**: report, even in `diff` scope: a local or shared database may already have applied them. Shape: collapse the branch's unmerged migrations into one regenerated against the default branch; never edit merged ones; deterministic or uncommitted schema dumps; CI checks for multiple heads and edits to merged migrations.
- **Keep when**: deliberate multi-step sequences: expand/contract, a backfill between schema changes, zero-downtime renames.

### Drive-by edits

- **Tell**: the diff touches files sharing no symbols with the core change; whitespace, import-order or quote-only hunks (`git diff -w --stat` against `git diff --stat`); renames inside a bug fix (`git diff -M --summary`); hunks rewriting lines from the last few commits with no behaviour change.
- **Do**: report, even in `diff` scope; never revert them yourself, since that discards someone's uncommitted work. List the hunks to split into their own commit or drop. Whitespace-only hunks route to "Layout the formatter doesn't own".
- **Keep when**: follow-on edits the change forces (lockfiles, generated output, call sites of a renamed symbol); cleanup inside lines already being changed; dedicated refactor commits; mechanical repo-wide changes isolated in one commit and listed in `.git-blame-ignore-revs`.
